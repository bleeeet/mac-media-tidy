# 媒体整理（media-kit）

本地网页工具，对一个文件夹一次性完成：

- **去重** — 内容完全相同的图片/视频只保留最早的一份
- **HEIC → JPG** — 保留 EXIF 与原始修改时间
- **视频压制** — 超标视频转为 H.265 / 1080p / 30fps / 约 2Mbps
- **图片瘦身** — 超过 3MB 的图片压到 3MB 以内

## 环境要求

- macOS（依赖系统自带的 `sips`）
- Node.js 20+
- `ffmpeg` 与 `ffprobe`：`brew install ffmpeg`

启动时会自动检测这些依赖，缺什么会在页面顶部提示。

## 使用

```bash
npm start
```

浏览器打开 <http://127.0.0.1:7788>，然后用以下任一方式指定文件夹：

1. **拖进页面** — 浏览器出于安全策略不暴露本地绝对路径，因此工具会拿文件夹名和几个样本文件，
   在 `~/Downloads`、`~/Desktop`、`~/Pictures`、`~/Documents`、`~/Movies` 及其两级子目录中反查。
   找到唯一匹配就直接开始；多个同名文件夹会列出来让你点选。
2. **粘贴路径** — Finder 里选中文件夹按 `⌘⌥C` 复制路径，贴进输入框。也接受从终端拖入的转义路径。
3. **点「浏览」** — 内置目录浏览器，从主目录逐级点入。

先看预演清单，确认后再点「开始处理」。扫描阶段是纯只读的，不会碰任何文件。

## 安全说明

本工具**从不直接删除文件**。所有被替换或判为重复的原件都会移动到目标文件夹下的 `_trash/`，
并在 `_trash/manifest.json` 中记录每一步操作，可据此手工回滚。确认结果无误后自行删除 `_trash/` 即可。

所有写入都走「临时文件 → 校验 → 原子重命名」，中途中断不会留下半个文件。单个文件出错只会
记入错误列表，不影响其余文件继续处理。

## 处理规则

| 项目 | 规则 |
|---|---|
| 去重判定 | 文件大小分组 + SHA-256 完全一致 |
| 保留哪一份 | 修改时间最早者；时间相同则取路径字典序最小的 |
| 视频压缩触发 | 长边 >1920 或 短边 >1080 或 帧率 >30 或 码率 >3Mbps |
| 视频输出 | `hevc_videotoolbox`，tag `hvc1`，2Mbps，音频 AAC 128k |
| 图片压缩触发 | 体积 >3MB |
| 图片质量档位 | 85 → 75 → 65 → 55，每档均从原图重新编码（不叠加有损压缩） |
| 带透明通道的 PNG | 不转 JPG，改用尺寸档位 4000 → 3000 → 2000 → 1500 逐级缩小 |
| 不处理的格式 | GIF / WebP / BMP 只参与去重，不做转换压缩 |
| 并发 | 视频 4，图片 CPU 核数，哈希 8 |

### 几个需要知道的行为

- **HEIC 转 JPG 后文件会变大**，通常是原来的 1.5–2 倍。HEIC 的压缩效率本就约为 JPEG 的两倍，
  换格式必然涨体积。工具会如实把这部分负收益从"节省空间"里扣掉。如果你只是想省空间而不在意
  格式，关掉「HEIC 转 JPG」开关即可。
- **竖屏视频不会被转横**。约束是「短边 ≤1080 且长边 ≤1920」，所以 1080×1920 保持原样，
  2160×3840 会缩成 1080×1920。
- **压完更大就放弃**。视频或图片如果处理后体积反而增加（且不是必须做的格式转换），
  工具会丢弃产物、保留原件，标记为「已跳过」。
- **已达标的文件完全不动**。1080p30 且码率正常的视频、3MB 以内的图片都会原样保留，
  不会为了"统一格式"而重压一遍。
- **关掉页面不影响处理**。任务在服务端继续跑，重新打开页面可以接上进度。

## 测试

```bash
npm test
```

端到端测试需要 `ffmpeg` 与 macOS 的 `sips`，缺失时对应用例会自动跳过。视频转码用例会实际
调用编码器，整轮耗时约 20–30 秒。
